Point de départ

Beaucoup de recherches “contrôlent pour” un certain nombre de variables dans leurs régressions / ANOVA. Pourquoi ? Et comment ça marche, sous le capot ?

Les copains et copines économistes m’ont appris deux-trois choses plutôt intéressantes sur ces sujets, et m’ont notammé familiarisé avec (1) le fonctionnement de la régression par moindres carrés2, (2) l’inférence causale et (3) la merveille qu’est le Théorème de Frisch-Waugh-Lovell, qui relie les deux premiers points.

Commençons donc par le commencement : commence ça fonctionne, la régression ? Tout cet article est globalement issu du formidable livre de Wooldridge (2025)3.

La régression

Le principe de base des régressions

L’analyse de régression est une méthode statistique pour résumer la relation entre une variable \(\mathbf{Y}\) à estimer4 et une ou des variables \(\mathbf{X}\) prédictives5.

C’est la formalisation (statistique) d’une théorie. Une théorie est une simplification de la réalité, c’est-à-dire du processus ayant généré les données. Un modèle revient donc à formaliser cette simplification, formaliser la réalité, sous des hypothèses.

Nos statistiques inférentielles ont (notamment) pour fonction d’estimer la valeur d’un paramètre dans une population, à partir d’un échantillon aléatoire issu de cette population.

Un modèle est (1) un signal et (2) une erreur, que Correll et al. (2025) résument sous l’équation suivante :

\[ \mathrm{données} = \mathrm{modèle} + \text{erreur} \]

Avec :

  • Les \(\mathrm{données}\) sont les observations recueillies ;
  • Le \(\mathrm{modèle}\) est une description des données ;
  • L’\(\text{erreur}\) est la différence entre ce que le \(\mathrm{modèle}\) estime et la \(\mathrm{données}\) observée.

L’\(\text{erreur}\) quantifie donc le degré d’inexactitude du \(\mathrm{modèle}\), elle est aussi appelée les résidus, ce qui reste après avoir estimé les \(\mathrm{données}\) à partir du \(\mathrm{modèle}\).

Le but de tout modèle est de résumer au mieux les données et la relation entre les variables, donc de réduire cette erreur.

Un modèle qui n’aurait qu’un paramètre imposé

Comment réduire l’erreur ? Je commence par un modèle avec un seul paramètre, une constante, aussi appelée intercept. Dit autrement, l’intercept est la valeur de \(\mathbf{Y}\) lorsque la droite de régression la croise.

J’impose un paramètre à ce modèle, la valeur de cet intercept. A l’œil, je lui impose la valeur 6.

\[ y_t = 6 + \varepsilon_t \label{eq-equationsix} \]

Avec :

  • \(y_t\) le score de satisfaction dans la vie pour l’observation \(t\)6. On parle parfois de variable dépendante, c’en est une ;
  • \(6\), la valeur imposée de l’intercept;
  • \(\varepsilon_t\) l’erreur.

Voilà ce que cela donnerait. Comme j’impose \(y_t = 6\), j’impose littéralement que chaque score de satisfaction estimé par le modèle, pour chaque observation, soit égal à \(6\).

Mathématiquement, les données recueillies sont notées \(y_t\). Les valeurs estimées par le modèle sont notées \(\hat{y_t}\).

Les résidus, c’est-à-dire l’écart entre le modèle estime (\(\hat{y_t} = 6\)) et les données recueillies (\(y_t\)), sont affichés en bleu7 :

Un modèle qui passerait par tous les points

# 1. Entraîner le modèle sur les 20 premières observations
fit_overfit_model <- function(data, n = 20) {
  d <- data %>%
    head(n = n) %>%
    mutate(id = row_number())
  
  lm(satisfaction ~ poly(id, n - 1), data = d) # ajustement d'un polynome de degré n-1, qui passe par tous les points
}

# 2. Tracer un jeu de données avec les prédictions du modèle entraîné sur head()
plot_overfit <- function(data, model, n = 20, tail = FALSE) {
  d <- if (tail) dplyr::slice_tail(data, n = n) else dplyr::slice_head(data, n = n)
  
  d <- d %>%
    mutate(id = row_number()) %>%
    mutate(pred = predict(model, newdata = .)) %>%
    mutate(id = as.factor(id))
  
  d %>%
    ggplot() +
    aes(x = id, y = satisfaction) +
    geom_point() +
    geom_line(
      aes(y = pred, group = 1), 
      color = "#0B6E6E"
      ) +
    labs(
      title = element_blank(),
      x = "Observation",
      y = "Satisfaction"
    ) +
    scale_y_continuous(limits = c(0, 10), n.breaks = 10) +
    theme_minimal()
}

# 3. Lancer la fonction 1 pour ajuster le modèle
model_overfit <- fit_overfit_model(df, n = 20)

# 4. Lancer la fonction 2 pour plot le modèle
plot_overfit(df, model_overfit, n = 20)

Est-ce un bon modèle ? A priori oui, le modèle est littéralement parfait : il passe exactement par tous les points et ne produit aucun résidu (aucune différence entre la donnée réelle et la donnée prédite par le modèle). Cependant, si un modèle doit réduire l’erreur, trop la réduire amène à un sur-ajustement.

Le sur-ajustement est un énorme problème, car un modèle doit estimer la valeur d’un paramètre dans une population. Si le modèle est sur-ajusté, il n’estime pas la valeur d’un paramètre dans une population, mais uniquement dans un échantillon.

Je représente cette fois-ci les 20 dernières observations, en gardant la ligne rouge des 20 premières observations. On voit que le modèle sur-ajusté ne généralise pas bien à un autre échantillon.

Voir le code

La régression par moindres carrés ordinaires (MCO)

L’?@eq-equationsix imposait un intercept de valeur \(6\). Il est possible de relâcher cette contrainte, via l’équation suivante :

\[ y_t = \beta_0 + \varepsilon_t \label{eq-equation_interceptonly} \]

Avec :

  • \(y_t\) le score de satisfaction dans la vie pour l’observation \(t\);
  • \(\beta_0\) un intercept;
  • \(\varepsilon_t\) l’erreur.

La contrainte a été relâchée en remplaçant la valeur \(6\) par le paramètre \(\beta_0\). Ce \(\beta_0\), on ne le connaît pas, c’est le modèle qui va l’estimer via un estimateur. Un estimateur est une fonction, un ensemble d’étapes à suivre permettant à un modèle d’estimer la valeur d’un paramètre inconnu.

En psychologie, l’estimateur le plus utilisé est celui des Moindres Carrés Ordinaires (MCO), ou Ordinary Least Squares (OLS).

Le principe des moindres carrés ordinaires est de résumer la relation entre une variable \(\mathbf{Y}\) et une ou des variables \(\mathbf{X}\) en estimant tout bêtement pas si bêtement la droite qui s’ajuste au mieux aux données en fonction du critère mathématique des moindres carrés. Cet ajustement du modèle via les moindres carrés ordinaires, c’est une autre façon de dire la droite qui réduit le mieux l’erreur.

L’estimateur des moindres carrés ordinaires va donc estimer la droite qui minimise la somme des écarts au carré entre cette droite et chaque observation. Pour chaque observation, l’écart entre la valeur prédite (la droite) et la valeur réelle (l’observation) est un résidu. Minimiser la somme des écarts au carré, c’est minimer ces résidus autant que possible.

Pourquoi estimer ? C’est, à nouveau, car les modèles sont inférentiels : ils estiment la valeur d’un paramètre dans une population à partir d’un échantillon aléatoire.

Cette explication peut être un peu complexe, on va directement voir des exemples.

Une régression linéaire par MCO avec un paramètre : l’intercept

Repartons des données simulées, en ne gardant que les 10 premières lignes pour l’exemple.

Pour commencer, j’ajuste le modèle de l’?@eq-equation_interceptonly avec un intercept uniquement. Avec un seul paramètre, ce modèle ne renvoie qu’une droite parallèle à l’axe des absisses, qui minimise au mieux la somme des écarts au carré sous cette contrainte. En demandant un peu d’aide à Claude, vous pouvez chercher vous-même combien vaut \(\beta_0\) pour la satisfaction dans la vie en faisant glisser le curseur.

La somme des écarts au carré la plus faible est estimée lorsque \(\beta_0\) vaut 6.90 : (-0.90)² + (-0.90)² + (-0.90)² + (0.10)² + (3.10)² + (-0.90)² + (0.10)² + (-0.90)² + (1.10)² + (0.10)² = 14.9000.

Cela signifie que cette valeur de \(\beta_0\) est la meilleure façon de résumer l’information, sous la double contrainte (1) de ne pouvoir utiliser qu’un paramètre, l’intercept ; et (2) sous l’estimateur des moindres carrés. Ce coefficient, c’est la moyenne arithmétique de la satisfaction dans la vie, et il y a une relation directe entre les moindres carrés et la moyenne.

Une régression linéaire par MCO avec un paramètre : la pente

Le modèle précédent résumait l’information contenue dans \(\mathbf{Y}\) par un seul paramètre, l’intercept \(\beta_0\). On recommence l’exercice avec un seul paramètre à nouveau, qui est cette fois-ci une pente8. Une pente ne peut pas exister seule, car elle multiplie un prédicteur, qui est ici le nombre d’heures de sommeil9.

L’équation est :

\[ y_t = \beta_1\, x_{t1} + \varepsilon_t \label{eq-equation_slopeonly} \]

Avec :

  • \(y_t\) le score de satisfaction dans la vie pour l’observation \(t\) ;
  • \(\beta_1\) la pente ;
  • \(x_{t1}\) le nombre d’heures de sommeil pour l’observation \(t\) ;
  • \(\varepsilon_t\) l’erreur.

Comparée à l’équation ?@eq-equation_interceptonly, cette dernière n’a pas de \(\beta_0\), elle n’a donc pas d’ordonnée à l’origine (de valeur de \(y\) lorsque \(x\) vaut zéro). Autrement dit, lorsque \(x\) vaut \(0\), \(y\) vaut nécessairement \(0\). Ce modèle impose donc une contrainte, en forçant la droite à passer par l’origine \((0, 0)\), c’est qu’une personne qui ne dormirait pas aurait forcément une satisfaction nulle. C’est une contrainte mathématique, qui est imposée au modèle.

On peut à nouveau visualiser ce modèle et chercher la meilleure valeur de \(\beta_1\) avec l’aide de Claude.

Une régression linéaire par MCO avec deux paramètres : un intercept et une pente

Modifions l’équation de la droite, en retirant la contrainte de faire passer l’intercept par \((0, 0)\). Il suffit d’ajouter un paramètre, \(\beta_0\), que le modèle va librement estimer.

Le modèle devient :

\[ y_t = \beta_0 + \beta_1\, x_{t1} + \varepsilon_t \label{eq-equation_slopeandintercept} \]

Avec :

  • \(y_t\) le score de satisfaction dans la vie pour l’observation \(t\) ;
  • \(\beta_0\) un intercept;
  • \(\beta_1\) la pente;
  • \(x_{t1}\) le nombre d’heures de sommeil pour l’observation \(t\) ;
  • \(\varepsilon_t\) l’erreur.

On pourrait continuer ces représentations graphiques des modèles de régression. Pour un modèle à deux paramètres et un intercept10, la figure passerait en trois dimensions et la visualisation serait un plan droit. Les résidus seraient l’écart entre ce plan droit et les données.

Pour un modèle à deux paramètres avec une interaction et un intercept11, la figure serait toujours en trois dimensions et la visualisation serait désormais un plan courbé. Les résidus seraient l’écart entre ce plan courbé et les données.

Un modèle à \(n \ge 3\) paramètres et plus ne pourrait pas être (facilement) représenté, car il deviendrait un hyperplan en \(\ge 3\) dimensions. Mathématiquement, la logique reste cependant la même.

Les bases de la régression étant (re) posées, on peut passer à la suite12.

Repartons de la question de départ

Notre question de départ était “Quel est l’effet du nombre d’heures de sommeil sur la satisfaction dans la vie d’une personne ?”

Pour rappel, j’ai simulé les données de satisfaction dans la vie, du nombre d’heures de sommeil et de sport la semaine précédente, pour 259 personnes. Je régresse donc la satisfaction dans la vie sur le nombre d’heures de sommeil la semaine précédente.

L’équation est :

\[ satisfaction_t = \beta_0 + \beta_1\, sommeil_t + \varepsilon_t \label{eq-reg_sommeil} \]

Avec :

  • \(satisfaction_t\) le score de satisfaction dans la vie de l’observation \(t\).
  • \(\beta_0\) est l’intercept du modèle ;
  • \(\beta_1\) est la pente, de combien le score de satisfaction augmente en moyenne lorsque les personnes dorment une heure de plus ;
  • \(x_{tj}\), \(j = 1, 2, \ldots, k\) sont les variables prédictrices, parfois appelées variables indépendantes ;
  • \(\varepsilon_t\) est l’erreur ;
Voir le code

L’intercept est la valeur de \(\mathbf{Y}\) lorsque la droite croise \(0\). Cela signifie qu’en moyenne, une personne qui rapporterait ne pas avoir dormi du tout la semaine précédente aurait un score de satisfaction dans la vie de 2.31. C’est une estimation, une extrapolation à partir de la droite de régression. Cela pose la question de savoir si une droite est une bonne façon de résumer la relation entre ces deux variables, car une personne qui n’aurait pas dormi du tout irait très certainement bien plus mal. Cela pose encore une autre question, car la droite s’étend à l’infini et le modèle pourrait tout à fait estimer la satisfaction dans la vie d’une personne qui aurait dormi -3 heures ou 31h par nuit la semaine précédente, ce qui n’est pas possible.

Le coefficient \(\beta_1\) est l’estimation, dans la population, de l’évolution moyenne de satisfaction dans la vie lorsqu’une personne dort une heure supplémentaire. En moyenne, quand une personne dort une heure supplémentaire, sa satisfaction dans la vie augmente de 0.71. C’est bien une moyenne ; certains personnes vont être très contentes sans dormir, d’autres vont directement être très mal suite à une mauvaise nuit.

Peut-on en déduire qu’une heure de sommeil supplémentaire cause une augmentation de la satisfaction de 0.71 ? Non. On peut par exemple penser que les personnes qui ont plus de temps pour faire du sport ont également plus de moyens financiers, ce qui leur permet d’avoir un cadre de vie général plus positif améliorant leur satisfaction dans la vie. On peut aussi faire l’hypothèse que cette augmentation découle du fait que les personnes qui font plus de sport sont plus fatiguées, donc dorment plus voire peut-être même mieux, et sont également plus satisfaites de leur vie de par les effets bénéfiques du sport. Etc, etc, etc…

Cette dernière hypothèse n’est pas absurde, à la vue des corrélations entre ces trois variables (Makowski et al., 2020).

Le principe de base d’une régression, quelque soit la méthode, est d’estimer une variable \(\mathbf{Y}\) à partir d’un ensemble de variables \(\mathbf{X}\). Très concrètement, cela signifie

Le principe de base d’une régression par les moindres carrés ordinaires est d’estimer une variable \(\mathbf{Y}\) à partir d’un ensemble de variables \(\mathbf{X}\).

Pour une régression à \(k\) paramètres, cela donne l’équation suivante :

\[ y_t = \beta_0 + \beta_1 x_{t1} + \beta_2 x_{t2} + \cdots + \beta_k x_{tk} + \varepsilon_t, \quad t = 1, 2, \ldots, n, \label{eq-equation_base} \]

  • \(y_t\) est la variable à estimer \(y\), pour l’observation \(t\)13. On parle parfois de variable dépendante, c’en est une ;
  • \(\beta_0\) est l’intercept du modèle ;
  • \(\beta_1, \ldots, \beta_k\) sont les pentes de chaque paramètre ;
  • \(x_{tj}\), \(j = 1, 2, \ldots, k\) sont les variables prédictrices, parfois appelées variables indépendantes ;
  • \(\varepsilon_t\) est l’erreur du modèle, c’est-à-dire ce que le modèle ne parvient pas à estimer, pour l’observation \(t\). On verra plus tard que cela amène à des résidus, qui seront le cœur du propos.

# La régression
## Le principe de base des régressions

L'analyse de régression est une méthode statistique pour résumer la relation entre une variable $\mathbf{Y}$ à estimer^[Aussi appelée *variable dépendante* en psychologie.] et une ou des variables $\mathbf{X}$ prédictives^[Aussi appelée *variable indépendante* en psychologie].

C'est la formalisation (statistique) d’une théorie. Une théorie est une simplification de la réalité, c'est-à-dire du processus ayant généré les données. Un modèle revient donc à formaliser cette simplification, formaliser la réalité, sous des hypothèses.

Nos statistiques inférentielles ont (notamment) pour fonction d'estimer la valeur d'un paramètre dans une population, à partir d'un échantillon aléatoire issu de cette population.

Un modèle est (1) un signal et (2) une erreur, que @correll2026 résument sous l'équation suivante :

$$
\mathrm{données} = \mathrm{modèle} + \text{erreur}
$$

Avec : 

- Les $\mathrm{données}$ sont les observations recueillies ;
- Le $\mathrm{modèle}$ est une description des données ;
- L'$\text{erreur}$ est la différence entre ce que le $\mathrm{modèle}$ estime et la $\mathrm{données}$ observée. 

L'$\text{erreur}$ quantifie donc le degré d’inexactitude du $\mathrm{modèle}$, elle est aussi appelée les *résidus*, ce qui reste après avoir estimé les $\mathrm{données}$ à partir du $\mathrm{modèle}$.

Le but de tout modèle est de résumer au mieux les données et la relation entre les variables, donc de *réduire* cette erreur.

## Un modèle qui n'aurait qu'un paramètre imposé

Comment réduire l'erreur ? Je commence par un modèle avec un seul paramètre, une constante, aussi appelée *intercept*. Dit autrement, l'intercept est la valeur de $\mathbf{Y}$ lorsque la droite de régression la croise.

J'impose un paramètre à ce modèle, la valeur de cet intercept. A l'œil, je lui impose la valeur 6.

$$
y_t = 6 + \varepsilon_t
\label{eq-equationsix}
$$

Avec :

- $y_t$ le score de satisfaction dans la vie pour l'observation $t$^[Remarquez que je ne parle pas d'une *personne* mais d'une *observation* : $t$ pourrait être la température relevée par un thermomètre, la vitesse d'un vélo, ou l'âge du capitaine.]. On parle parfois de variable dépendante, c'en est une ;
- $6$, la valeur imposée de l'intercept;
- $\varepsilon_t$ l'erreur.

Voilà ce que cela donnerait. Comme j'impose $y_t = 6$, j'impose *littéralement* que chaque score de satisfaction estimé par le modèle, pour chaque observation, soit égal à $6$. 

Mathématiquement, les données recueillies sont notées $y_t$. Les valeurs estimées par le modèle sont notées $\hat{y_t}$.

# La régression par moindres carrés ordinaires (MCO)

L'@eq-equationsix imposait un intercept de valeur $6$. Il est possible de relâcher cette contrainte, via l'équation suivante : 

$$
y_t = \beta_0 + \varepsilon_t
\label{eq-equation_interceptonly}
$$

Avec :

- $y_t$ le score de satisfaction dans la vie pour l'observation $t$;
- $\beta_0$ un intercept;
- $\varepsilon_t$ l'erreur.

La contrainte a été relâchée en remplaçant la valeur $6$ par le paramètre $\beta_0$. Ce $\beta_0$, on ne le connaît pas, c'est le modèle qui va l'estimer via un *estimateur*. Un estimateur est une fonction, un ensemble d'étapes à suivre permettant à un modèle d'estimer la valeur d'un paramètre inconnu. 

En psychologie, l'estimateur le plus utilisé est celui des Moindres Carrés Ordinaires (MCO), ou Ordinary Least Squares (OLS).

Le principe des moindres carrés ordinaires est de résumer la relation entre une variable $\mathbf{Y}$ et une ou des variables $\mathbf{X}$ en estimant ~~tout bêtement~~ pas si bêtement la droite qui s'ajuste au mieux aux données *en fonction du critère mathématique des moindres carrés*. Cet ajustement du modèle via les moindres carrés ordinaires, c'est une autre façon de dire *la droite qui réduit le mieux l'erreur*.

L'estimateur des moindres carrés ordinaires va donc **estimer la droite qui minimise la somme des écarts au carré entre cette droite et chaque observation**. Pour chaque observation, l'écart entre la valeur prédite (la droite) et la valeur réelle (l'observation) est un *résidu*. Minimiser la somme des écarts au carré, c'est minimer ces résidus autant que possible.

Pourquoi *estimer* ? C'est, à nouveau, car les modèles sont inférentiels : ils estiment la valeur d'un paramètre dans une population à partir d'un échantillon aléatoire.

Cette explication peut être un peu complexe, on va directement voir des exemples.

  // ---- generic OLS: solve the normal equations (intercept first) ------------
  function solveOLS(cols, y) {
    const m = cols.length + 1, N = y.length;
    const get = (j, t) => (j === 0 ? 1 : cols[j - 1][t]);
    const A = Array.from({ length: m }, () => new Array(m).fill(0));
    const v = new Array(m).fill(0);
    for (let i = 0; i < m; i++) {
      for (let j = 0; j < m; j++) {
        let s = 0;
        for (let t = 0; t < N; t++) s += get(i, t) * get(j, t);
        A[i][j] = s;
      }
      let s = 0;
      for (let t = 0; t < N; t++) s += get(i, t) * y[t];
      v[i] = s;
    }
    for (let i = 0; i < m; i++) {            // Gaussian elimination, pivoting
      let p = i;
      for (let r = i + 1; r < m; r++)
        if (Math.abs(A[r][i]) > Math.abs(A[p][i])) p = r;
      [A[i], A[p]] = [A[p], A[i]]; [v[i], v[p]] = [v[p], v[i]];
      const piv = A[i][i];
      for (let j = i; j < m; j++) A[i][j] /= piv;
      v[i] /= piv;
      for (let r = 0; r < m; r++) {
        if (r === i || !A[r][i]) continue;
        const f = A[r][i];
        for (let j = i; j < m; j++) A[r][j] -= f * A[i][j];
        v[r] -= f * v[i];
      }
    }
    return v;

## Une régression linéaire par MCO avec un paramètre : la pente

Le modèle précédent résumait l'information contenue dans $\mathbf{Y}$ par un seul paramètre, l'*intercept* $\beta_0$. On recommence l'exercice avec un seul paramètre à nouveau, qui est cette fois-ci une *pente*^[Si ce vocabulaire vous perd, pensez à une montagne : certaines faces sont plus ou moins pentues. C'est la même idée ici.]. Une pente ne peut pas exister seule, car elle multiplie un prédicteur, qui est ici le nombre d'heures de sommeil^[Une pente qui ne multiple aucun prédicteur est un intercept, une valeur stable.].

L'équation est :

$$
y_t = \beta_1\, x_{t1} + \varepsilon_t
\label{eq-equation_slopeonly}
$$

Avec :

- $y_t$ le score de satisfaction dans la vie pour l'observation $t$ ;
- $\beta_1$ la pente ;
- $x_{t1}$ le nombre d'heures de sommeil pour l'observation $t$ ;
- $\varepsilon_t$ l'erreur.

Comparée à l'équation @eq-equation_interceptonly, cette dernière n'a pas de $\beta_0$, elle n'a donc pas d'ordonnée à l'origine (de valeur de $y$ lorsque $x$ vaut zéro). Autrement dit, lorsque $x$ vaut $0$, $y$ vaut nécessairement $0$. Ce modèle impose donc une contrainte, en forçant la droite à passer par l'origine $(0, 0)$, c'est qu'une personne qui ne dormirait pas aurait *forcément* une satisfaction nulle. C'est une contrainte mathématique, qui est imposée au modèle.

On peut à nouveau visualiser ce modèle et chercher la meilleure valeur de $\beta_1$ avec l'aide de Claude.

## Une régression linéaire par MCO avec deux paramètres : un intercept et une pente

Modifions l'équation de la droite, en retirant la contrainte de faire passer l'intercept par $(0, 0)$. Il suffit d'ajouter un paramètre, $\beta_0$, que le modèle va librement estimer.

Le modèle devient : 

$$
y_t = \beta_0 + \beta_1\, x_{t1} + \varepsilon_t
\label{eq-equation_slopeandintercept}
$$

Avec :

- $y_t$ le score de satisfaction dans la vie pour l'observation $t$ ;
- $\beta_0$ un intercept;
- $\beta_1$ la pente;
- $x_{t1}$ le nombre d'heures de sommeil pour l'observation $t$ ;
- $\varepsilon_t$ l'erreur.

# Repartons de la question de départ

Notre question de départ était "Quel est l'effet du nombre d'heures de sommeil sur la satisfaction dans la vie d'une personne ?"

Pour rappel, j'ai simulé les données de satisfaction dans la vie, du nombre d'heures de sommeil et de sport la semaine précédente, pour `r nrow(df)` personnes.  Je régresse donc la satisfaction dans la vie sur le nombre d'heures de sommeil la semaine précédente.

L'équation est :

$$
satisfaction_t = \beta_0 + \beta_1\, sommeil_t + \varepsilon_t
\label{eq-reg_sommeil}
$$

Avec :

- $satisfaction_t$ le score de satisfaction dans la vie de l'observation $t$. 
- $\beta_0$ est l'intercept du modèle ;
- $\beta_1$ est la pente, de combien le score de satisfaction augmente en moyenne lorsque les personnes dorment une heure de plus ;
- $x_{tj}$, $j = 1, 2, \ldots, k$ sont les variables prédictrices, parfois appelées variables indépendantes ;
- $\varepsilon_t$ est l'erreur ;

L'intercept est la valeur de $\mathbf{Y}$ lorsque la droite croise $0$. Cela signifie qu'en moyenne, une personne qui rapporterait ne pas avoir dormi du tout la semaine précédente aurait un score de satisfaction dans la vie de `r round(lm_sommeil[["coefficients"]][["(Intercept)"]], 2)`. C'est une estimation, une extrapolation à partir de la droite de régression. Cela pose la question de savoir si une droite est une bonne façon de résumer la relation entre ces deux variables, car une personne qui n'aurait pas dormi du tout irait très certainement bien plus mal. En moyenne, quand une personne dort une heure supplémentaire, sa satisfaction dans la vie augmente de `r round(lm_sommeil[["coefficients"]][["sommeil"]], 2)`.

Etc, etc, etc...

Cette dernière hypothèse n'est pas absurde, à la vue des corrélations entre ces trois variables [@makowski2020].

Ces trois variable sont très corrélées :

- Plus la personne dort et plus elle fait du sport ;
- Plus la personne dort et plus elle est satisfaite de sa vie ;
- Plus la personne fait du sport et plus elle est satisfaite de sa vie. 

Elles renforçent l'idée que la satisfaction dans la vie est influencée à la fois par le nombre d'heures de sommeil et par la pratique sportive. En conséquence, régresser la satisfaction dans la vie sur le nombre d'heures de sommeil uniquement confond l'effet du sommeil et l'effet du sport. Sauf si... on *contrôle pour* le nombre d'heures de sport. 

## Pourquoi *contrôler pour* une variable ?

*Contrôler pour* est quelque chose d'extrêmement complexe, à partir du moment où l'on souhaite bien le faire. De manière générale, il ne faudrait contrôler que les variables dont on estime qu'elles causent à la fois les prédicteurs et les variables qui nous intéressent [@acrashcourse]. Ici, la table de corrélations montre qu'il est plausible de penser que le nombre d'heures de sommeil est influencé par la pratique sportive, et que la satisfaction dans sa vie est également influencée par le nombre d'heures de sommeil. Théoriquement, l'hypothèse pourrait également se tenir.

Si l'on faisait un DAG, il ressemblerait à ça [@acrashcourse] : 

```{r}

#| fig-cap: "Le DAG de notre étude fictive."

  satisfaction ~ sommeil + sport,
  sommeil ~ sport,
  labels = c(

    "sommeil" = "Nbr. d'heures de sommeil",
    "sport" = "Nbr. d'heures de sport"

  exposure = "sommeil",
  outcome = "satisfaction"
) %>%
  
  ggdag(
    text = FALSE, 
    use_labels = "label"
  ) +

```

# Comment *contrôler pour*

Ici, rien (ou presque) de plus simple, une régression *par moindres carrés ordinaires* fait le travail. On régresse la satisfaction sur le sommeil, la satisfaction sur le sport, et la satisfaction sur le sommeil *et* le sport.

Cela donne trois équations distinctes : 



$$
satisfaction_t = \beta_0 + \beta_1\, sport_t + \varepsilon_t
\label{eq-reg_sport}
$$

$$
satisfaction_t = \beta_0 + \beta_1\, sommeil_t + \beta_2\, sport_t + \varepsilon_t
\label{eq-reg_complet}
$$

Dont voici les résultats [@modelsummary] : 

```{r}
#| label: tbl-regressions
#| tbl-cap: "Les résultats des trois régressions."

lm_sommeil <- lm(satisfaction ~ sommeil, df)
lm_sport <- lm(satisfaction ~ sport, df)
lm_sommeil_sport <- lm(satisfaction ~ sommeil + sport, df)

list_regressions <- list(
  "Satisfaction sur sommeil (1)" = lm_sommeil,
  "Satisfaction sur sport (2)" = lm_sport,
  "Satisfaction sur sommeil et sport (3)" = lm_sommeil_sport
)

library(modelsummary)

modelsummary(
  list_regressions, 
  coef_rename = c(
    "sommeil" = "Nbr. d'heures de sommeil",
    "sport" = "Nbr. d'heures de sport"
  ),
  stars = T
)
```

La régression (1) indique que, pour chaque heure de sommeil supplémentaire, le score de satisfaction dans la vie augmente de `r round(lm(satisfaction ~ sommeil, df)[["coefficients"]][["sommeil"]], 2)`; la régression (2) que, pour chaque heure de sport supplémentaire, le score de satisfaction dans la vie augmente de `r round(lm(satisfaction ~ sport, df)[["coefficients"]][["sport"]], 2)`. La régression (3), celle qui *contrôle pour*, estime que pour chaque heure supplémentaire dormie, la satisfaction dans la vie augmente de `r round(lm(satisfaction ~ sommeil + sport, df)[["coefficients"]][["sommeil"]], 2)`. C'est plus faible que le coefficient estimé dans l'équation (1). 

La question désormais est de savoir ce que ce chiffre signifie, ce que *contrôler pour* signifie. Et pour ça, il faut mettre un peu les mains dans le cambouis de la régression.










J'estime désormais trois régressions : 

L'idée, assez simple, serait que le sommeil est important pour la satisfaction dans sa vie, mais que la pratique d'une activité sportive l'est également et pourrait expliquer une partie du lien.



Le principe de base d'une régression, *quelque soit la méthode*, est d'estimer une variable $\mathbf{Y}$ à partir d'un ensemble de variables $\mathbf{X}$. Très concrètement, cela signifie

Le principe de base d'une régression *par les moindres carrés ordinaires* est d'estimer une variable $\mathbf{Y}$ à partir d'un ensemble de variables $\mathbf{X}$.

Pour une régression à $k$ paramètres, cela donne l'équation suivante :

$$
y_t = \beta_0 + \beta_1 x_{t1} + \beta_2 x_{t2} + \cdots + \beta_k x_{tk} + \varepsilon_t, \quad t = 1, 2, \ldots, n,
\label{eq-equation_base}
$$

Ici : 

- $y_t$ est la variable à estimer $y$, pour l'observation $t$^[Remarquez que je ne parle pas d'une *personne* mais d'une *observation* : $t$ pourrait être la température relevée par un thermomètre, la vitesse d'un vélo, ou l'âge du capitaine.]. On parle parfois de variable dépendante, c'en est une ;
- $\beta_0$ est l'intercept du modèle ;
- $\beta_1, \ldots, \beta_k$ sont les pentes de chaque paramètre ;
- $x_{tj}$, $j = 1, 2, \ldots, k$ sont les variables prédictrices, parfois appelées variables indépendantes ;
- $\varepsilon_t$ est l'erreur du modèle, c'est-à-dire ce que le modèle ne parvient pas à estimer, pour l'observation $t$. On verra plus tard que cela amène à des résidus, qui seront le cœur du propos.
